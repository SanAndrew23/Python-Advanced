Классы и объекты, __init__

Объектно-ориентированное программирование (ООП) — это парадигма, в которой программа строится из объектов, объединяющих данные (атрибуты) и поведение (методы). Класс — это шаблон (чертёж), по которому создаются объекты.

Ключевые понятия ООП

  • Класс — описание структуры и поведения будущих объектов.
  • Объект (экземпляр) — конкретный экземпляр класса с собственными данными.
  • Атрибут — переменная, принадлежащая объекту или классу.
  • Метод — функция, определённая внутри класса.
  • self — ссылка на текущий объект, первый параметр каждого метода экземпляра.

Объявление класса

Первый класс: описание собаки

class Dog:
    def __init__(self, name, breed, age):
        self.name = name
        self.breed = breed
        self.age = age

    def bark(self):
        return f"{self.name} говорит: Гав!"

    def info(self):
        return f"{self.name} ({self.breed}), {self.age} лет"


rex = Dog("Рекс", "Немецкая овчарка", 3)
buddy = Dog("Бадди", "Лабрадор", 5)

print(rex.bark())   # Рекс говорит: Гав!
print(buddy.info()) # Бадди (Лабрадор), 5 лет
print(rex.name)     # Рекс

Атрибуты класса vs атрибуты экземпляра

Атрибуты класса разделяются всеми экземплярами, а атрибуты экземпляра — уникальны для каждого объекта.

Атрибуты класса и экземпляра

class Counter:
    count = 0  # атрибут класса

    def __init__(self, name):
        Counter.count += 1
        self.name = name      # атрибут экземпляра
        self.id = Counter.count

    def __repr__(self):
        return f"Counter(name={self.name!r}, id={self.id})"


a = Counter("alpha")
b = Counter("beta")
c = Counter("gamma")

print(a)             # Counter(name='alpha', id=1)
print(b)             # Counter(name='beta', id=2)
print(Counter.count) # 3 — одно значение для всех

Метод __init__ — это инициализатор, а не конструктор

Технически конструктором в Python является __new__, который создаёт объект. __init__ лишь инициализирует уже созданный объект. В повседневной работе переопределяют именно __init__.

Удаление атрибутов и объектов

del и __del__

class Resource:
    def __init__(self, name):
        self.name = name
        print(f"Ресурс {self.name} создан")

    def __del__(self):
        print(f"Ресурс {self.name} освобождён")


r = Resource("файл")  # Ресурс файл создан
del r                 # Ресурс файл освобождён

Осторожно с __del__

Не полагайтесь на __del__ для критически важной логики освобождения ресурсов — время его вызова не гарантировано. Используйте контекстный менеджер (with + __enter__/__exit__) для детерминированного управления ресурсами.

Наследование и super()

Наследование позволяет создать новый класс (дочерний) на основе существующего (родительского), переиспользуя и расширяя его функциональность.

class Дочерний(Родительский):
    def __init__(self, ...):
        super().__init__(...)  # вызов __init__ родителя
        self.доп_атрибут = ...

Базовый пример: животные

class Animal:
    def __init__(self, name, sound):
        self.name = name
        self.sound = sound

    def speak(self):
        return f"{self.name} говорит: {self.sound}"

    def __str__(self):
        return f"Animal({self.name!r})"


class Dog(Animal):
    def __init__(self, name):
        super().__init__(name, "Гав!")
        self.tricks = []

    def learn_trick(self, trick):
        self.tricks.append(trick)
        return f"{self.name} научился: {trick}"


class Cat(Animal):
    def __init__(self, name, indoor=True):
        super().__init__(name, "Мяу!")
        self.indoor = indoor


rex = Dog("Рекс")
print(rex.speak())              # Рекс говорит: Гав!
print(rex.learn_trick("сидеть"))  # Рекс научился: сидеть

whiskers = Cat("Усатик")
print(whiskers.speak())         # Усатик говорит: Мяу!

Проверка принадлежности к классу

isinstance и issubclass

print(isinstance(rex, Dog))    # True
print(isinstance(rex, Animal)) # True — Dog наследует Animal
print(isinstance(rex, Cat))    # False

print(issubclass(Dog, Animal)) # True
print(issubclass(Cat, Animal)) # True
print(issubclass(Dog, Cat))    # False

Множественное наследование

Python поддерживает множественное наследование. Порядок разрешения методов определяется алгоритмом MRO (Method Resolution Order) — линеаризацией C3.

Множественное наследование и MRO

class Flyable:
    def move(self):
        return "Лечу"

    def describe(self):
        return "Умею летать"


class Swimmable:
    def move(self):
        return "Плыву"

    def describe(self):
        return "Умею плавать"


class Duck(Flyable, Swimmable):
    def quack(self):
        return "Кря!"


donald = Duck()
print(donald.move())     # Лечу — Flyable идёт первым в MRO
print(donald.quack())    # Кря!

print(Duck.__mro__)
# (<class 'Duck'>, <class 'Flyable'>, <class 'Swimmable'>, <class 'object'>)

Зачем super(), а не прямой вызов родителя?

super() корректно следует MRO, что особенно важно при множественном наследовании. Прямой вызов Animal.__init__(self, ...) может привести к пропуску инициализации одного из классов в цепочке.

Магические методы

Магические методы (dunder-методы, от double underscore) — это специальные методы с именами вида __имя__. Python вызывает их автоматически в ответ на определённые операции: создание объекта, сравнение, арифметику, итерацию и многое другое.

__str__ str(obj), print(obj) Читаемое представление
__repr__ repr(obj), в интерактивной оболочке Отладочное представление
__len__ len(obj) Размер объекта
__eq__ obj1 == obj2 Проверка равенства
__lt__, __le__ и т.д. obj1 < obj2 Сравнение

__str__ и __repr__

Строковые представления объекта

class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __repr__(self):
        return f"Point({self.x!r}, {self.y!r})"

    def __str__(self):
        return f"({self.x}, {self.y})"


p = Point(3, 4)
print(str(p))     # (3, 4)     — для пользователя
print(repr(p))    # Point(3, 4) — для разработчика
print(p)          # (3, 4)     — print вызывает __str__

points = [Point(1, 2), Point(3, 4)]
print(points)     # [Point(1, 2), Point(3, 4)] — в списке repr

Правило: __repr__ должен позволять воссоздать объект

Идеальный __repr__ возвращает строку, которую можно передать в eval() и получить эквивалентный объект. Если это невозможно — строка должна быть максимально информативной.

__eq__, __lt__ и операторы сравнения

Сравнение объектов

from functools import total_ordering


@total_ordering
class Temperature:
    def __init__(self, celsius):
        self.celsius = celsius

    def __repr__(self):
        return f"Temperature({self.celsius}°C)"

    def __eq__(self, other):
        if not isinstance(other, Temperature):
            return NotImplemented
        return self.celsius == other.celsius

    def __lt__(self, other):
        if not isinstance(other, Temperature):
            return NotImplemented
        return self.celsius < other.celsius


t1 = Temperature(20)
t2 = Temperature(35)
t3 = Temperature(20)

print(t1 == t3)  # True
print(t1 < t2)   # True
print(t2 > t1)   # True  — @total_ordering даёт __gt__ бесплатно
print(t1 != t2)  # True

temps = [t2, t1, Temperature(10)]
print(sorted(temps))  # [Temperature(10°C), Temperature(20°C), Temperature(35°C)]

__len__, __getitem__ и протокол последовательности

Класс-коллекция

class Playlist:
    def __init__(self, name):
        self.name = name
        self._tracks = []

    def add(self, track):
        self._tracks.append(track)

    def __len__(self):
        return len(self._tracks)

    def __getitem__(self, index):
        return self._tracks[index]

    def __contains__(self, track):
        return track in self._tracks

    def __iter__(self):
        return iter(self._tracks)

    def __repr__(self):
        return f"Playlist({self.name!r}, {len(self)} треков)"


pl = Playlist("Мой плейлист")
pl.add("Song A")
pl.add("Song B")
pl.add("Song C")

print(len(pl))           # 3
print(pl[0])             # Song A
print("Song B" in pl)    # True

for track in pl:
    print(track)
# Song A
# Song B
# Song C

Арифметические магические методы

Векторная арифметика

import math


class Vector:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __repr__(self):
        return f"Vector({self.x}, {self.y})"

    def __add__(self, other):
        return Vector(self.x + other.x, self.y + other.y)

    def __sub__(self, other):
        return Vector(self.x - other.x, self.y - other.y)

    def __mul__(self, scalar):
        return Vector(self.x * scalar, self.y * scalar)

    def __rmul__(self, scalar):
        return self.__mul__(scalar)

    def __neg__(self):
        return Vector(-self.x, -self.y)

    def __abs__(self):
        return math.sqrt(self.x ** 2 + self.y ** 2)

    def __bool__(self):
        return self.x != 0 or self.y != 0


v1 = Vector(1, 2)
v2 = Vector(3, 4)

print(v1 + v2)    # Vector(4, 6)
print(v2 - v1)    # Vector(2, 2)
print(v1 * 3)     # Vector(3, 6)
print(3 * v1)     # Vector(3, 6) — через __rmul__
print(-v1)        # Vector(-1, -2)
print(abs(v2))    # 5.0
print(bool(Vector(0, 0)))  # False

__call__ — вызываемые объекты

Объект как функция

class Adder:
    def __init__(self, step):
        self.step = step

    def __call__(self, value):
        return value + self.step

    def __repr__(self):
        return f"Adder(step={self.step})"


add5 = Adder(5)
add10 = Adder(10)

print(add5(3))    # 8
print(add10(3))   # 13
print(callable(add5))  # True

numbers = [1, 2, 3, 4]
print(list(map(add5, numbers)))  # [6, 7, 8, 9]

Контекстный менеджер: __enter__ и __exit__

Собственный контекстный менеджер

class Timer:
    import time as _time

    def __enter__(self):
        import time
        self._start = time.perf_counter()
        return self

    def __exit__(self, exc_type, exc_val, exc_tb):
        import time
        self.elapsed = time.perf_counter() - self._start
        print(f"Прошло: {self.elapsed:.4f} сек")
        return False  # не подавлять исключения


with Timer() as t:
    total = sum(range(1_000_000))

print(f"Сумма: {total}")
# Прошло: 0.0123 сек
# Сумма: 499999500000

Полиморфизм

Полиморфизм (от греч. «многоформность») — способность объектов разных типов реагировать на один и тот же интерфейс. В Python полиморфизм достигается через переопределение методов, утиную типизацию и абстрактные классы.

Утиная типизация

«Если это выглядит как утка, крякает как утка — это утка.» Python не требует явного наследования; достаточно, чтобы объект поддерживал нужный интерфейс (имел нужные методы/атрибуты).

Полиморфизм через переопределение методов

class Shape:
    def area(self):
        raise NotImplementedError

    def perimeter(self):
        raise NotImplementedError

    def describe(self):
        return (
            f"{type(self).__name__}: "
            f"площадь={self.area():.2f}, "
            f"периметр={self.perimeter():.2f}"
        )


class Circle(Shape):
    def __init__(self, r):
        self.r = r

    def area(self):
        import math
        return math.pi * self.r ** 2

    def perimeter(self):
        import math
        return 2 * math.pi * self.r


class Rectangle(Shape):
    def __init__(self, w, h):
        self.w = w
        self.h = h

    def area(self):
        return self.w * self.h

    def perimeter(self):
        return 2 * (self.w + self.h)


class Triangle(Shape):
    def __init__(self, a, b, c):
        self.a, self.b, self.c = a, b, c

    def area(self):
        s = self.perimeter() / 2
        return (s * (s - self.a) * (s - self.b) * (s - self.c)) ** 0.5

    def perimeter(self):
        return self.a + self.b + self.c


shapes = [Circle(5), Rectangle(4, 6), Triangle(3, 4, 5)]

for shape in shapes:
    print(shape.describe())
# Circle: площадь=78.54, периметр=31.42
# Rectangle: площадь=24.00, периметр=20.00
# Triangle: площадь=6.00, периметр=12.00

Абстрактные классы

Модуль abc позволяет объявить интерфейс явно: абстрактный класс нельзя создать, не реализовав все его абстрактные методы.

Использование ABC и abstractmethod

from abc import ABC, abstractmethod


class Serializable(ABC):
    @abstractmethod
    def serialize(self) -> str:
        """Преобразует объект в строку."""

    @abstractmethod
    def deserialize(self, data: str):
        """Восстанавливает объект из строки."""

    def save_to_file(self, path: str):
        with open(path, "w", encoding="utf-8") as f:
            f.write(self.serialize())


class JSONUser(Serializable):
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def serialize(self) -> str:
        import json
        return json.dumps({"name": self.name, "age": self.age})

    def deserialize(self, data: str):
        import json
        d = json.loads(data)
        self.name = d["name"]
        self.age = d["age"]
        return self


user = JSONUser("Алиса", 30)
print(user.serialize())  # {"name": "\u0410\u043b\u0438\u0441\u0430", "age": 30}

# Попытка создать экземпляр ABC вызовет TypeError:
# s = Serializable()  # TypeError: Can't instantiate abstract class

Проверка реализации интерфейса

isinstance(obj, Serializable) вернёт True, если класс объекта наследует Serializable и реализует все абстрактные методы. Это позволяет строить надёжные, самодокументирующиеся интерфейсы.

Инкапсуляция

Инкапсуляция — сокрытие внутренней реализации объекта и предоставление контролируемого доступа к данным через публичный интерфейс. В Python используется соглашение об именовании и механизм name mangling.

Уровни доступа в Python

Именование Уровень Описание
attr Публичный Доступен всем
_attr Защищённый (условно) Соглашение: «только для внутреннего использования»
__attr Приватный (name mangling) Python переименует в _ClassName__attr

Одинарное и двойное подчёркивание

class BankAccount:
    def __init__(self, owner, balance):
        self.owner = owner          # публичный
        self._transaction_log = []  # защищённый (соглашение)
        self.__balance = balance    # приватный (name mangling)

    def deposit(self, amount):
        if amount <= 0:
            raise ValueError("Сумма должна быть положительной")
        self.__balance += amount
        self._transaction_log.append(f"+{amount}")

    def withdraw(self, amount):
        if amount <= 0:
            raise ValueError("Сумма должна быть положительной")
        if amount > self.__balance:
            raise ValueError("Недостаточно средств")
        self.__balance -= amount
        self._transaction_log.append(f"-{amount}")

    def get_balance(self):
        return self.__balance

    def __repr__(self):
        return f"BankAccount({self.owner!r}, balance={self.__balance})"


acc = BankAccount("Алиса", 1000)
acc.deposit(500)
acc.withdraw(200)

print(acc.get_balance())        # 1300
print(acc._transaction_log)     # ['+500', '-200']

# acc.__balance                 # AttributeError!
print(acc._BankAccount__balance)  # 1300 — можно обойти, но не нужно

Python не имеет настоящей приватности

Name mangling (__attr → _ClassName__attr) — это защита от случайных коллизий при наследовании, а не полноценная инкапсуляция. Технически атрибут __balance можно прочитать как _BankAccount__balance. Инкапсуляция в Python — это соглашение, которое разработчики уважают, а не языковое ограничение.

Слоты (__slots__)

__slots__ явно ограничивает набор атрибутов экземпляра, экономит память и ускоряет доступ к атрибутам за счёт отказа от внутреннего словаря __dict__.

Использование __slots__

class Point:
    __slots__ = ("x", "y")

    def __init__(self, x, y):
        self.x = x
        self.y = y

    def distance(self):
        return (self.x ** 2 + self.y ** 2) ** 0.5


p = Point(3, 4)
print(p.distance())  # 5.0

# p.z = 10  # AttributeError: 'Point' object has no attribute 'z'
# print(p.__dict__)  # AttributeError: 'Point' object has no attribute '__dict__'

Методы класса и статические методы

Помимо обычных методов экземпляра, Python поддерживает методы класса (@classmethod) и статические методы (@staticmethod).

Три вида методов

Декоратор Первый параметр Доступ к Когда использовать
нет self экземпляру и классу Большинство методов
@classmethod cls только классу Альтернативные конструкторы, фабрики
@staticmethod нет ничему Вспомогательные функции, логически связанные с классом

classmethod как альтернативный конструктор

class Date:
    def __init__(self, year, month, day):
        self.year = year
        self.month = month
        self.day = day

    @classmethod
    def from_string(cls, date_str):
        year, month, day = map(int, date_str.split("-"))
        return cls(year, month, day)

    @classmethod
    def today(cls):
        import datetime
        d = datetime.date.today()
        return cls(d.year, d.month, d.day)

    @staticmethod
    def is_leap_year(year):
        return year % 4 == 0 and (year % 100 != 0 or year % 400 == 0)

    def __repr__(self):
        return f"Date({self.year}, {self.month:02d}, {self.day:02d})"


d1 = Date(2024, 3, 15)
d2 = Date.from_string("2024-07-04")
d3 = Date.today()

print(d1)  # Date(2024, 03, 15)
print(d2)  # Date(2024, 07, 04)

print(Date.is_leap_year(2024))  # True
print(Date.is_leap_year(2023))  # False

Свойства (property)

Декоратор @property позволяет создавать управляемые атрибуты: обращение к атрибуту внешне выглядит как доступ к полю, но внутри вызывается метод. Это ключевой инструмент инкапсуляции в Python.

@property
def имя(self):           # getter — вызывается при чтении obj.имя
    return self._имя

@имя.setter
def имя(self, value):    # setter — вызывается при записи obj.имя = value
    self._имя = value

@имя.deleter
def имя(self):           # deleter — вызывается при del obj.имя
    del self._имя

Валидация через property

class Circle:
    def __init__(self, radius):
        self.radius = radius  # вызывает setter

    @property
    def radius(self):
        return self._radius

    @radius.setter
    def radius(self, value):
        if value < 0:
            raise ValueError(f"Радиус не может быть отрицательным: {value}")
        self._radius = value

    @property
    def diameter(self):
        return self._radius * 2

    @property
    def area(self):
        import math
        return math.pi * self._radius ** 2

    def __repr__(self):
        return f"Circle(radius={self._radius})"


c = Circle(5)
print(c.radius)    # 5
print(c.diameter)  # 10
print(f"{c.area:.2f}")  # 78.54

c.radius = 7
print(c.diameter)  # 14

# c.radius = -1    # ValueError: Радиус не может быть отрицательным: -1

Вычисляемые свойства — температура

class Temperature:
    def __init__(self, celsius=0):
        self.celsius = celsius

    @property
    def celsius(self):
        return self._celsius

    @celsius.setter
    def celsius(self, value):
        if value < -273.15:
            raise ValueError("Температура ниже абсолютного нуля!")
        self._celsius = value

    @property
    def fahrenheit(self):
        return self._celsius * 9 / 5 + 32

    @fahrenheit.setter
    def fahrenheit(self, value):
        self.celsius = (value - 32) * 5 / 9

    @property
    def kelvin(self):
        return self._celsius + 273.15

    def __repr__(self):
        return f"{self._celsius}°C / {self.fahrenheit:.1f}°F / {self.kelvin:.2f}K"


t = Temperature(100)
print(t)            # 100°C / 212.0°F / 373.15K

t.fahrenheit = 32
print(t)            # 0.0°C / 32.0°F / 273.15K

Dataclasses

Декоратор @dataclass из модуля dataclasses автоматически генерирует __init__, __repr__, __eq__ и другие методы на основе аннотаций типов. Это современный и лаконичный способ создания классов-данных.

Сравнение обычного класса и dataclass

from dataclasses import dataclass, field
from typing import List


# Обычный класс — много шаблонного кода
class ProductOld:
    def __init__(self, name, price, tags=None):
        self.name = name
        self.price = price
        self.tags = tags if tags is not None else []

    def __repr__(self):
        return f"Product(name={self.name!r}, price={self.price}, tags={self.tags})"

    def __eq__(self, other):
        return (self.name, self.price) == (other.name, other.price)


# dataclass — минимум кода
@dataclass
class Product:
    name: str
    price: float
    tags: List[str] = field(default_factory=list)

    def discounted(self, percent: float) -> "Product":
        return Product(self.name, self.price * (1 - percent / 100), self.tags)


p1 = Product("Кофе", 250.0, ["горячие", "напитки"])
p2 = Product("Кофе", 250.0)
p3 = p1.discounted(10)

print(p1)             # Product(name='Кофе', price=250.0, tags=['горячие', 'напитки'])
print(p1 == p2)       # True — __eq__ сгенерирован
print(p3.price)       # 225.0

Параметры @dataclass

from dataclasses import dataclass


@dataclass(frozen=True, order=True)
class Point:
    x: float
    y: float

    def distance(self) -> float:
        return (self.x ** 2 + self.y ** 2) ** 0.5


p1 = Point(0, 0)
p2 = Point(3, 4)
p3 = Point(1, 1)

print(p2.distance())     # 5.0
print(sorted([p2, p1, p3]))  # [Point(x=0, y=0), Point(x=1, y=1), Point(x=3, y=4)]

# p1.x = 5  # FrozenInstanceError — frozen=True запрещает изменения

# frozen=True позволяет использовать объект как ключ словаря
coords = {p1: "начало координат", p2: "точка B"}
print(coords[Point(0, 0)])  # начало координат

Параметры декоратора @dataclass

  • eq=True — генерировать __eq__ (по умолчанию).
  • order=True — генерировать методы сравнения (<, > и т.д.).
  • frozen=True — запретить изменение атрибутов (иммутабельность).
  • slots=True — использовать __slots__ (Python 3.10+).
  • kw_only=True — все поля принимаются только как keyword-аргументы (Python 3.10+).

Итого: что выбрать?

  • Нужна полная логика (методы, сложная инициализация) → обычный класс.
  • Класс в основном хранит данные → @dataclass.
  • Иммутабельный объект-значение → @dataclass(frozen=True).
  • Нужен именованный кортеж → typing.NamedTuple.
